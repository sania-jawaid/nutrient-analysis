## Problem and scope

This module is a CPU-friendly prototype for reading nutrition-panel images, extracting OCR text and geometry, associating a nutrient label with a value/unit when layout evidence is sufficient, and returning basis-aware JSON. It is separate from the Part 1 EDA and Streamlit dashboard; those files and data are not changed.

## Dataset and annotations

Source: [Open Food Facts Nutrient Detection Layout](https://huggingface.co/datasets/openfoodfacts/nutrient-detection-layout), CC-BY-SA 3.0. The inspected revision has 2,884 train and 199 test examples in the `default` configuration. Each sample has `tokens`, `bboxes`, `ner_tags`, `image`, and `meta`; the exact 71-id BIO mapping is in `dataset.py`.

The dataset card says OCR tokens/boxes were generated by Google Cloud Vision and annotators label nutrient values/units, not usually nutrient names. The annotations are not manually verified transcription truth for evaluating EasyOCR. Rule-based table extraction and BIO token classification are different tasks.

The ordinary demo loader uses the dataset-server row API with a configurable
1–50 image subset per split; explicit row-index access also supports the
full-cohort runner's original row refreshes. Images are downloaded lazily and
cached under `data/part2_cache/images`. The linked annotation inventory contains
all 3,083 images, including eight without product matches; matched-cohort
inference intentionally targets 3,075 only. Official splits are preserved.
The loader demo uses train by default and does not tune rules against labels.

## Open Food Facts pretrained BIO tagger

`part2/layoutlm_bio.py` integrates Open Food Facts' already fine-tuned [nutrition-extractor](https://huggingface.co/openfoodfacts/nutrition-extractor) LayoutLMv3-large checkpoint. Model revision is pinned to `4c28d479f332339ffc367d9aae66036a4583127c`; model license is CC-BY-NC-SA-4.0. It is a separate model-based BIO predictor and runs locally on CPU only. The preferred local checkpoint is `part2/weights/model.onnx`; a local `model.safetensors` is supported as fallback.

- Inputs are an image, the official dataset OCR words, and corresponding boxes in `[0,1000]`; the processor's saved settings resize/normalize the image and do not run OCR itself.
- The manually supplied checkpoint and prediction cache are at `part2/weights/` and `data/part2_cache/layoutlm_bio/` respectively. The small config/tokenizer companion files are kept beside the ONNX file. The model checkpoint itself is gitignored.
- The published ONNX checkpoint is 1,429,090,779 bytes (~1.33 GiB). ONNX Runtime uses sequential CPU execution, one intra-op thread, and disabled memory-pattern caching. The local loader never downloads weights. It checks available physical RAM before opening the checkpoint and refuses to proceed below 2.5 GiB; the larger Transformers fallback requires 6 GiB.
- Install optional dependencies with `pip install -e ".[bio-inference]"`. This installs ONNX Runtime CPU and the Transformers processor runtime, but does not fetch model weights. If sidecar files are missing, only the small config/tokenizer files are needed; the 1.43 GB checkpoint is never fetched by the code.
- The separate notebook `part2_layoutlm_bio_tagging.ipynb` attempts one official test image first, then a fixed-seed 20-image evaluation. The existing dashboard retains one-/three-image actions and adds a separate 20-image action. No model-card metrics are reported as local measurements.
- Adaptive overlapping OCR-word windows map first-subword logits to original positions and average overlap logits. Uncovered words trigger smaller windows; unresolved coverage raises an error rather than inventing O labels. Prediction cache keys and dashboard bundles carry an inference schema version.
- Structured JSON retains raw tokens/tags, BIO spans, nutrient/basis/unit/value, normalized quantities, qualifiers and uncertainty reasons. Duplicate/conflicting fields, missing units and ambiguous numeric spans remain flagged rather than silently resolved.
- Uploaded images use cached EasyOCR weights on CPU with `download_enabled=False` and `quantize=False`, followed by the same ONNX predictor. Whitespace-split words share their parent OCR detection box; those are not measured word boxes. Uploads have no gold labels or claimed accuracy.
- Field-tuple evaluation against decoded official `ner_tags` discloses unparseable gold exclusions. Optional API checks cover at most 10 barcodes and remain separate weak-metadata comparisons, never visual gold or BIO results.

Actual measurements and error examples are recorded in [the measured evaluation report](../reports/part2/bio_pipeline_findings.md). The fixed-seed run completed 20/20 images with 1,551/1,551 words covered; the original three-image truncation case now covers 453/453 instead of 391/453. These are subset results, not full-test or independent OCR benchmarks.

The follow-up [completion review for tasks 5–8](../reports/part2/bio_remaining_tasks_findings.md) adds conditional numerical accuracy (174/178 on saved dataset predictions), actual model-versus-rule evaluation on the existing manual reference (5/16 versus 1/16 exact gold fields), OCR transcription differences, parsing diagnostics and downloadable dashboard reports. The one manual image is not a population benchmark. `part2/bio_review.py` holds reusable exact field scoring and provenance-validated review loading; the original gold files remain unchanged.

The fine-grained model labels and existing rule labels describe different taxonomies. For a meaningful rule comparison, model and rule predictions are projected to shared coarse `VALUE` / `BASIS` / `O` spans and scored against the same projected gold spans and original OCR tokens. EasyOCR is not included in positional BIO metrics unless token alignment is independently verified. Inference reports exact-span precision/recall/F1, token accuracy, elapsed time, and process RSS/available-RAM changes only when actual local inference completes; no model-card metrics are substituted.

## Architecture

See [architecture.md](architecture.md) for the Mermaid pipeline, component responsibilities, actual annotation taxonomy and explicitly non-executable supervised-training pseudocode.

## Why EasyOCR

EasyOCR provides a practical open-source OCR interface for Windows with CPU mode, configurable language packs, text detections, polygon boxes, and per-detection scores. That makes it a suitable replaceable baseline for preserving layout evidence. EasyOCR is lazy-loaded; the reader is reused and its weights are not downloaded unless explicitly authorized. It is not assumed to be accurate on every language or nutrition-table layout.

## Implemented components

- EXIF-aware image loading and configurable RGB/resize/contrast/grayscale preprocessing.
- EasyOCR adapter with CPU-only execution, shared reader, configurable languages, reading-order sorting, graceful error result, and content-addressed OCR JSON cache.
- Nutrient alias matching, decimal-comma and unit normalization, row-based spatial association, basis column anchoring, and unresolved-field reporting.
- JSON-compatible extraction schema and structural validation.
- Bounded official-split PyTorch Dataset, variable-length custom collator and CPU DataLoader demo.
- OCR, structured-field, and aligned BIO evaluation helpers.
- Manual-verified-gold fixtures and unit tests. Test fixtures are not extraction accuracy evidence.

## Training design

- This repository does not train or fine-tune the Open Food Facts model. `part2/train.py` remains a no-training placeholder.
- Do not compare EasyOCR token predictions to dataset BIO tags by position without verified token alignment.
- The heuristic row/column association is not a robust table structure parser. Review unresolved or repeated values manually.

## Install

Optional processing setup, not needed for cached dashboard browsing. From the
project root, using **Python 3.10–3.12** and a CPU PyTorch build on Windows:

```powershell
python -m pip install torch --index-url https://download.pytorch.org/whl/cpu
python -m pip install -e ".[easyocr,test,bio-inference]"
```

This installs CPU PyTorch, OCR/test packages, and the optional Transformers/ONNX inference runtimes. It does not download either EasyOCR weights or the LayoutLM checkpoint. EasyOCR's own weights remain separately gated. ONNX Runtime is installed in the active project virtual environment for the local ONNX checkpoint.

## Load a small annotated batch

```powershell
python -m part2.inference --demo-loader --limit 2 --batch-size 2
```

The command prints the selected official split, barcode strings, token counts, tensor dimensions, example tokens/labels, and image size. Only those image files are fetched; it does not fetch the complete dataset. To inspect official test samples without OCR, run `python -m part2.inference --demo-loader --split test --limit 2`.

## Inference

```powershell
python -m part2.inference --image path/to/image.jpg --barcode 0123456789012 --output outputs/prediction.json
```

If the OCR weights are already cached, inference preprocesses the image, runs EasyOCR on CPU, performs conservative association, validates and writes JSON. Without cached OCR weights it writes a result with an explicit `ocr_error` and exits nonzero; no OCR text/result is fabricated. Language and preprocessing options can be set on the CLI (`--languages en,fr`, `--max-side`, `--contrast`, `--grayscale`).

Bounded dataset-image inference (not label evaluation):

```powershell
python -m part2.inference --dataset-split train --limit 2 --output outputs/train_predictions.jsonl
```

Never select the test split during rule development. Use the official test only after choices are frozen.

## Evaluation

```powershell
python -m part2.evaluation
```

The output is explicitly marked as an illustrative fixture that validates metric code only. For OCR CER/WER, pass manually transcribed `verified: true` references to `evaluate_verified_ocr`. If there are no such references, OCR accuracy is reported as `not_established`. Structured extraction metrics need independently reviewed gold nutrient/value/unit/basis records. BIO entity precision/recall/F1 requires aligned predicted and gold tokens, and the function refuses to run unless token alignment is explicitly marked verified.

## Future fine-tuning boundary

`python -m part2.train` does not train or fetch weights. Any future project-specific fine-tuning must use verified annotations, product-grouped splits, subword label alignment, and a locked test set. This integration only loads the separate Open Food Facts checkpoint for inference. The generic `nutrition-train` CLI is a different executable scaffold and must not be mistaken for this placeholder.

## Why CPU-compatible

EasyOCR is explicitly constructed with `gpu=False`; the PyTorch dataset and collator use CPU tensors, `pin_memory=False`, and default `num_workers=0`. The rule-based extraction has no accelerator dependency. The optional LayoutLM training design is not run.

## Limitations

- Image-based OCR only runs if EasyOCR weights are available locally or the user explicitly authorizes model downloads.
- English is the default OCR language; the training labels contain multilingual product panels. Set suitable EasyOCR languages per run.
- Table row/column structure and nutrient aliases are heuristic; ambiguous candidates are returned unresolved.
- OCR confidence is not calibrated extraction confidence.
- One existing manually reviewed panel has transcription and 16 structured reference fields, with separate [OCR](../reports/part2_ocr_validation/review_summary.md) and [model/rule follow-up](../reports/part2/bio_remaining_tasks_findings.md) snapshots. It lacks aligned manual word-box BIO gold and is not sufficient for population OCR/extraction claims. Those runs use different scoring conventions; do not merge their figures.
- The published BIO labels annotate values/units; nutrient names and row relations are not generally supervised.
